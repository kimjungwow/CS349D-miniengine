\section{Objective}
This milestone upgrades the scheduler from naive single-request execution to:
\begin{enumerate}
  \item batched decode (multiple requests in one forward pass), and
  \item continuous batching (iteration-level admission/removal each scheduler step).
\end{enumerate}
The goal is to improve throughput while keeping generation quality/correctness unchanged.

\section{Baseline and Design}
\subsection{Baseline}
The baseline scheduler handles one request at a time:
\begin{enumerate}
  \item prefill one request,
  \item decode it until completion,
  \item move to the next request.
\end{enumerate}
This underutilizes the GPU because decode runs as many thin matrix-vector operations instead of a larger batched matrix-matrix operation.

\subsection{Milestone 1 Design}
I implemented two changes:
\begin{enumerate}
  \item \textbf{Batched decode}: stack each running request's last generated token and run one batched forward call per decode iteration.
  \item \textbf{Continuous batching}: in every scheduler step, admit new requests (up to \texttt{max\_running}), prefill admitted requests, decode all active requests once, then retire finished requests.
\end{enumerate}

\subsection{Model/Attention Interface}
I threaded an optional \texttt{attn\_mask} through:
\texttt{Attention} $\rightarrow$ \texttt{TransformerBlock} $\rightarrow$ \texttt{TransformerModel} $\rightarrow$ \texttt{CausalLM}.
When the mask is present, it is passed to \texttt{scaled\_dot\_product\_attention}; otherwise the original causal path is used.

\subsection{Batched Decode and KV Cache Handling}
For a batch with per-request cache lengths $\{L_i\}$:
\begin{enumerate}
  \item Compute \texttt{max\_cache\_len = max($L_i$)}.
  \item Pad each request's per-layer KV cache to \texttt{max\_cache\_len}.
  \item Build an attention mask over key positions \texttt{K = max\_cache\_len + 1}.
  \item Run one batched decode forward pass.
  \item For request $i$, keep old valid KV prefix \texttt{[:,:,$:L_i$,:]} and append only the newly generated token KV.
\end{enumerate}

\subsection{Mask Correctness Note}
The decode mask marks valid positions as:
\begin{itemize}
  \item old real cache tokens \texttt{[0, $L_i$)},
  \item and the newly appended token at \texttt{max\_cache\_len}.
\end{itemize}
Padding region between \texttt{$L_i$} and \texttt{max\_cache\_len-1} is masked out.
Mask shape is \texttt{(B, 1, 1, K)}.
